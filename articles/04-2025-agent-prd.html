Agent 来了之后，需求文档还怎么写

2025 年我改 PRD 比改原型多：Agent 要写的是目标、禁区、权限和可回放轨迹，不是第三页聊天框截图。

2025 年第三季度，我一份 Agent 需求被研发打了回来三次。不是估时不准，是 PRD 里没写清「它能不能自动改生产配置」。

以前 PRD 擅长画页面和字段。Agent 上线后，用户一句话，系统自己选工具、跑几步、失败要不要重试——这些若不在文档里，就等于把决策留给模型临场发挥。

我先强制对齐定义

文档里必须写：自主程度（建议 / 需确认 / 策略内自动）、工具范围（读哪些、写哪些）、时间跨度（一次请求还是跨小时任务）。不开会统一语言，后面权限和验收全漂。

工作流变在哪

从设计唯一路径，变成设计目标和禁区。从写页面，变成写状态和轨迹——用户走了，Agent 还在跑，跑成什么样要看得见。验收从「结果截图」，变成「过程可审计」。评审从功能清单，变成风险清单：重试、幂等、提示注入、谁签字。

PRD 我强制加的章节

任务定义（可验证的句子）、成功标准（业务 + 过程约束）、工具清单（输入输出、失败码、谁审批写操作）、人机交接（暂停、改道、终止）、轨迹展示（给用户和管理员）、安全（注入、越权、敏感数据）。缺一章就不排期。

验收怎么写才不假

不只「能完成任务」，要「失败可恢复、越权被拒绝、轨迹可导出、关键写操作有二次确认」。用剧本测：正常、工具超时、用户中途改口、恶意提示注入。每条剧本期望状态，不是期望文案。

跟研发对齐的一句话

「你们实现规划，我定义能规划到哪里。」边界划清，Agent 才好迭代；划不清，每次线上事故都是新产品。
